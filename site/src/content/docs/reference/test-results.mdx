## How it's graded

Each case has a few checks, stored next to its prompt in [`scripter/evals/`](https://github.com/MichaelCodeToLimit/scripter/tree/main/scripter/evals):

- **Judged verdict.** Three AI judges read the answer against a written rubric, for example: *"PASS if it identifies that household tap pressure through a small turbine delivers far too little power … and backs this with at least one rough number."* The majority vote decides. The folding-stool case also has a judged check of its load path.
- **Praise.** A pattern check that fails the answer for phrases such as "great idea", "I love this" or "hope this helps".
- **Length.** Cases where the right answer is short (a small question, a sound design, an obvious no) fail if the reply runs past a limit of 1,500–2,500 characters.
- **Built before checking.** Cases where it must stop for your OK fail if the reply already contains 3D modelling code.
- **Builds.** Once you have approved the design, the reply must contain the code.
- **Stays out of the way.** The birthday message is not design work, so it fails if the skill turns on.
- **Skill fired.** Whether the skill loaded on design prompts. This is reported but not scored, since it can't apply to the run without the skill.

A case passes only if every scored check passes.

## Run it yourself

The suite uses `claude plugin eval`. From the repo root:

```bash
claude plugin eval ./scripter --ablation with-without --model sonnet --runs 1 --no-publish
```

It uses your Claude plan's allowance. To show a new run on this site, set `RESULTS_RUN` in `site/scripts/sync-skill.mjs` to its results folder and push. See [Customize and rebuild](/scripter/reference/customize/).
